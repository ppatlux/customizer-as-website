Simon Says

Now the cube has four coloured buttons and a 13-LED ring. It flashes a growing sequence of colours — one, then two, then three — and you play it back on the buttons. Each colour has its own tone, so you can learn the pattern by ear as well as by sight. There's a single-player mode with a saved high score and a pass-the-pattern multiplayer mode.

⏱ 35–50 min 🐍 MicroPython 🧠 Memory game 4 buttons + buzzer

A colour is just an index 0–3 everywhere in this program: it picks the button, the RGB tuple, the tone, and (via the map below) which LEDs light. Keep that in mind and the whole file reads easily.

2 · Colour index → physical LEDs

The ring has 13 LEDs. LED 0 is the white centre "power" light; the other 12 are split into four arcs of three. COLOR_LED_MAP hides that wiring so the rest of the code only ever thinks in colour indexes:

COLOR_LED_MAP = {
    0: [2, 3, 4],     # Red arc
    1: [5, 6, 7],     # Green arc
    2: [8, 9, 10],    # Blue arc
    3: [11, 12, 1],   # Yellow arc — wraps past LED 0
}

def show_color(index, color, brightness=0.3):
    dimmed = tuple(int(c * brightness) for c in color)
    for led in COLOR_LED_MAP[index]:
        np[led] = dimmed
    np.write()
Everything is drawn at brightness=0.3. NeoPixels at full power are blinding and eat current — dim them.

3 · Reading a button

The four buttons live in a list. wait_for_button() blocks until one is pressed, confirms it after 50 ms (debounce), waits for release, and returns its index:

def wait_for_button():
    while True:
        for i, button in enumerate(buttons):
            if button.value() == 0:          # PULL_UP: pressed = 0
                time.sleep(0.05)
                if button.value() == 0:      # still down = real press
                    while button.value() == 0:
                        time.sleep(0.01)      # wait for release
                    return i
        time.sleep(0.01)

Simon Says can afford to just stop and wait like this — unlike Ring Chase, it never races a clock. That blocking-vs-polling choice is the real difference between a memory game and a timing game.

4 · The sequence is a list

The whole game state is one list of colour indexes, e.g. [2, 0, 3, 3, 1]. Each round appends a random one:

sequence.append(random.randint(0, 3))

play_sequence() shows it back — flash_color() lights the arc, plays the tone, pauses, clears. Then an input loop checks your presses in order and bails the moment one is wrong:

for expected in sequence:
    pressed = wait_for_button()
    flash_color(pressed, duration=0.15)     # quick echo of your input
    if pressed != expected:
        error_sound()                       # 150 Hz buzz
        game_over_effect()                  # 3x red pulse
        ...save high score if beaten...
        return

Clear the sequence, update_score_leds(level) lights a purple progress meter, play_level_up_sound(), and the next round is one longer.

5 · Two modes, same pieces

Both modes are built from the same primitives (play_sequence, wait_for_button, flash_color):

  • Single player — the cube adds each new step; you only repeat. Your score is level - 1 (you failed on a level, so cleared the one before), saved to highscore.txt if it beats the stored best.
  • Multiplayer — players alternate; on your turn you repeat the sequence and then add a step of your own. Miss and the other player wins (victory_jingle()). The turn flips with one line: current_player = 3 - current_player.

The menu at the bottom lights LED 3 orange (RED = single) and LED 6 cyan (GREEN = multi) and waits on wait_for_button().
