Inside the Retro Console

The model on the left is a handheld games console built on the HP Robot board: an 8 × 16 LED screen, two buttons, a rotary knob and a buzzer — running a full game of Tetris. The complete program is on the Python code panel for this mix (console.py). This lesson walks through how it works so you can change it.

⏱ 45–60 min 🐍 MicroPython 🔌 Digital I/O only 🖨 1 printed shell

1 · The parts it talks to

Every input and output is wired to a fixed pin. There are no analog sensors here — the console reads digital inputs (buttons, encoder) and drives digital outputs (the LED matrix, the buzzer).

PartTypeJobPin
LED matrix (8×16)outputThe screen — 128 addressable RGB LEDsGP18
Left buttoninputMove piece leftGP27
Right buttoninputMove piece rightGP14
Rotary encoderinputRotate piece (two signals: CLK, DT)GP21 / GP22
BuzzeroutputSound effects and musicGP25

The buttons and encoder are set up with Pin.PULL_UP, so an untouched pin reads 1 and a pressed one reads 0. The matrix is a NeoPixel strip physically folded into a grid. The buzzer is passive — you make tone by sending it a square wave.

2 · The screen is just a list of lights

A NeoPixel matrix is one long chain of LEDs. The code treats it as a grid by converting an (x, y) position into a position in that chain:

# pixel (x, y) -> index in the 128-LED chain
np[y * WIDTH + x] = (r, g, b)

Two helpers do all the drawing every frame: draw_grid() paints the blocks that have already landed, then draw_piece() paints the piece you're controlling on top. Both run every loop, then np.write() pushes the colours out to the hardware.

Every colour is passed through scale_color(), which multiplies it by BRIGHTNESS = 0.3. At full brightness a packed screen draws a lot of current and the colours wash out — keep values low.

3 · Reading the controls

Buttons

Because of the pull-ups, pressed means the value is 0. The loop also remembers the previous reading (last_btn_left, last_btn_right) so one press moves the piece one step instead of sliding it across the screen while you hold the button — that's edge detection.

# move only on the 1 -> 0 transition (the moment of pressing)
if last_btn_left == 1 and curr_left == 0:
    if valid_position(px - 1, py, current_piece['shape']):
        px -= 1
        blip()

Rotary knob (encoder)

An encoder sends two square waves, CLK and DT, that are slightly out of step. When CLK changes, the level of DT at that instant tells you which way it turned:

if clk_now != last_clk:                       # CLK edge = one detent
    if time.ticks_diff(now, move_timer) > 100:  # ignore contact bounce
        rotate_piece(clockwise=(clk_now != dt_now))
        click()
last_clk = clk_now

4 · The game loop never sleeps

The piece has to fall on its own and the buttons have to feel instant. You can't sleep() — that would freeze input. Instead the loop runs flat out and each activity checks a stopwatch, time.ticks_ms(), to decide if it's due:

  • fall_timer + fall_interval — drop the piece one row (500 ms normally, 75 ms when both buttons are held: the fast drop).
  • move_timer + move_delay — how often a held button repeats, and encoder debounce.
if time.ticks_diff(now_ms, fall_timer) > fall_interval:
    fall_timer = now_ms
    if valid_position(px, py + 1, current_piece['shape']):
        py += 1
    else:
        freeze_piece(); thud(); remove_lines(); new_piece()

This "check a timer, don't block" pattern is how one loop juggles several things at once on a microcontroller.

5 · Pieces, rotation & collision

The 7 tetrominoes live in SHAPES as plain data: each shape is a list of its 4 rotation states, and each state is a list of 4 cells given as (dx, dy) offsets from the piece's position.

# the T piece: 4 rotations, each 4 cells
[[(0,0),(1,0),(2,0),(1,1)],
 [(1,0),(1,1),(1,2),(0,1)],
 [(0,1),(1,1),(2,1),(1,0)],
 [(1,0),(1,1),(1,2),(2,1)]]

Rotating doesn't do any maths — it just moves to the next state in the list. And there's one rule for whether any move is allowed, valid_position(), reused by left/right moves, rotation and gravity alike:

def valid_position(x0, y0, shape):
    for dx, dy in shape:
        x, y = x0 + dx, y0 + dy
        if x < 0 or x >= WIDTH or y >= HEIGHT:
            return False                 # off the screen
        if y >= 0 and grid[y][x] != (0, 0, 0):
            return False                 # hits a settled block
    return True

rotate_piece() builds the rotated shape, tests it with that function, and only keeps it if it fits — so a rotation against a wall is simply ignored.

6 · Landing, line clears & scoring

When gravity finds no valid spot below, freeze_piece() copies the piece's cells into grid for good. Then remove_lines() rebuilds the grid keeping only the rows that aren't full, and drops blank rows in on top:

new_grid = [row for row in grid if not all(p != (0,0,0) for p in row)]
cleared  = HEIGHT - len(new_grid)
while len(new_grid) < HEIGHT:
    new_grid.insert(0, [(0,0,0)] * WIDTH)
score += cleared * 10                    # then jingle()

If new_piece() spawns a shape that's already invalid, the stack reached the top — game_over() plays a sad tone, scrolls your score, saves the high score and resets.

7 · Sound & memory

The buzzer is driven with PWM — a square wave whose frequency is the pitch:

def buzz(freq, dur=100, duty=200):
    buzzer.freq(freq); buzzer.duty(duty)
    time.sleep_ms(dur); buzzer.duty(0)

Short named helpers (blip, click, thud, jingle, sad_tone) call it with set pitches, and play_tetris_theme() plays the Korobeiniki melody as a list of (freq, duration) pairs on boot. The high score is written to highscore.txt on the board's own filesystem, so it survives a power-off.

Try it

Open console.py in the editor above, run it, then change one thing at a time:

  • EASYSpeed the game up: lower fall_interval from 500.
  • EASYRecolour the pieces in SHAPE_COLORS.
  • MEDScore more for multi-line clears: make score += cleared * cleared * 10.
  • MEDAdd a sound on rotate — call blip() inside rotate_piece() when the rotation is accepted.
  • HARDAdd a "next piece" preview in the top row using draw_piece's idea on a second mini-area.
Then design the shell on the left: paint the body and the buttons in contrasting colours, check no parts show a red clash badge, and use Print / Download on each piece to send it to your slicer.
